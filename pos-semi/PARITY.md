## 对照中发现的后端缺陷（已修代码，待部署）

`add_to_cart` 读取 `productPrice` 时只按字符串解析；PostgreSQL `numeric` 在 JSON 中返回**数字**，
导致购物车单价/小计/合计恒为 `0.00`（legacy 线上同样复现）。

- 修复：`rust/crates/services/src/pos/cashier.rs` 新增 `json_decimal()`，同时兼容字符串与数字；
- 验证：`productPrice` 实测为 `9.9`（number）；已部署并复核：加购 2 件 → 单价 9.90 / 小计 19.80 / 合计 19.80。

另发现：`createTourists` / `createMember` 因 `user.email` 等列 NOT NULL 且无默认值而 500
（`null value in column "email"`）。已修 `user_insert_pos`，显式写入空串；待下一次 staging 部署。

## 后端能力缺口（阻塞 100% 对齐）

对照 legacy 请求体发现 Rust 侧尚未实现的部分：

| 能力 | legacy 行为 | Rust 现状 |
|---|---|---|
| 整单改价 | `cart/changePriceShow` 传 `totalChangePriceType` + `changePriceValue` | ✅ 已实现摊分与预览；单行展示价未区分 |
| 收银结账 | 无桌台收银、优惠券/余额/积分/备注 | ✅ 已实现；带 tableId 时自动清台 |
| 会员充值 | 现金充值 | ✅ 已实现充值单 + 余额入账 + 流水；在线支付未接 |
| 优惠券 | 可见列表/领取/下单核销 | 列表与领取已实现，下单核销未接 |

结论：收银台剩余功能（改价、结账、充值、优惠券）需要先补后端，再回到前端对齐。
